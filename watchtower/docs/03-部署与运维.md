# 部署与运维

## 一、最快跑起来（Docker）

```bash
cd watchtower/deploy
cp watchtower.example.json watchtower.json      # 改里面的 api_token
export WATCHTOWER_API_TOKEN='换成足够长的随机串'
docker compose up -d

docker compose exec watchtower python -m watchtower platforms   # 看支持哪些平台
docker compose exec watchtower python -m watchtower discover    # 扫局域网 ONVIF 设备
```

接入小米/米家且 go2rtc 直连不稳时，额外起 Micam：

```bash
docker compose --profile xiaomi up -d
```

## 二、裸机部署

```bash
cd watchtower/server
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -r requirements-ai.txt      # 可选：检测/打码/解说能力

sudo apt install ffmpeg                 # 必需：分段录制与剪影合成

python -m watchtower init               # 生成 watchtower.json
# 编辑 watchtower.json：至少设置 api_token 与 go2rtc.public_base_url

# 另起一个终端跑 go2rtc（二进制从 github.com/AlexxIT/go2rtc 下载）
./go2rtc -config ../deploy/go2rtc.yaml

python -m watchtower serve
```

## 三、加摄像头

各平台参数见 [`01-平台接入调研.md`](01-平台接入调研.md)。

```bash
W="python -m watchtower"

# 通用 RTSP（海康/大华/宇视/杂牌 NVR）
$W add-camera --name 前院 --zone 前院 --platform generic \
  -o url='rtsp://admin:pass@192.168.1.64:554/Streaming/Channels/101'

# ONVIF 自动问设备要地址（换型号不用改配置）
$W add-camera --name 后门 --platform onvif \
  -o mode=onvif -o host=192.168.1.65 -o username=admin -o password=pass

# 萤石 EZVIZ
$W add-camera --name 大门 --platform ezviz \
  -o app_key=xxx -o app_secret=yyy -o device_serial=ABC123 -o protocol=hls

# 乐橙 Imou
$W add-camera --name 仓库 --platform imou \
  -o app_id=xxx -o app_secret=yyy -o device_id=ZZZ -o protocol=hls

# 涂鸦 Tuya
$W add-camera --name 车库 --platform tuya \
  -o client_id=xxx -o client_secret=yyy -o device_id=vdevo123 -o region=cn

# 小米/米家（uid/did/model 从米家账号导出）
$W add-camera --name 客厅 --platform xiaomi \
  -o mode=go2rtc -o uid=1234567890 -o region=cn -o ip=192.168.1.123 \
  -o did=9876543210 -o model=isa.camera.hlc7

# 360（没有可服务端拉的公开接口，二选一）
$W add-camera --name 门口 --platform 360 -o mode=manual -o url='rtsp://…'
$W add-camera --name 门口 --platform 360 -o mode=relay -o stream_name=door360

$W cameras         # 看各路状态
```

## 四、推送

```bash
python -m watchtower push-test --channel bark --target <你的 device key>
python -m watchtower sub-add --channel bark --target <key> --label 我的手机
```

也可以直接在 App 的「监控 → 设置」里填，会先测试再订阅。

| 通道 | target 填什么 |
| --- | --- |
| `bark` | Bark device key，或完整的 `https://自建域名/KEY` |
| `wecom` | 企业微信群机器人 webhook 完整地址 |
| `dingtalk` | 钉钉 webhook，加签的话写成 `webhook|secret` |
| `telegram` | `<bot_token>\|<chat_id>` |
| `webhook` | 任意 URL，收到统一结构的 JSON |

**Web Push / FCM** 需要 VAPID 签名与负载加密（`pywebpush`）或 Google OAuth（`google-auth`），
不在默认依赖里。App 在前台时走 SSE 已经是秒达，上面这些通道负责"把人叫回来"，
对家庭/小团队足够；确实需要原生推送再自行接入。

## 五、公网访问（重要）

**不要把 8900 端口直接暴露到公网。** 两种推荐做法：

**A. 反向代理 + HTTPS**（Caddy 为例）

```caddy
watch.example.com {
    reverse_proxy 127.0.0.1:8900
    # SSE 需要关闭缓冲
    header /api/stream/* {
        -Content-Encoding
        Cache-Control no-cache
    }
}
go2rtc.example.com {
    reverse_proxy 127.0.0.1:1984
}
```

然后把 `go2rtc.public_base_url` 设成 `https://go2rtc.example.com`，
App 里的服务端地址填 `https://watch.example.com`。

**B. 只走内网**（更省心）：WireGuard / Tailscale 组网，App 连内网地址，不开任何公网端口。

无论哪种，`api_token` 必须设置。启动时若为空会打警告：

```
未设置 api_token —— 任何人都能访问你的摄像头，公网部署务必配置！
```

## 六、检测器选型

`analysis.detector` 默认 `auto`，按 `yolo → onnx → motion → stub` 逐档降级，装什么用什么。

| 档位 | 依赖 | 大致占用（1080p, 2fps, 单路） | 适合 |
| --- | --- | --- | --- |
| `yolo` | ultralytics(+torch) | CPU 高 / 有 GPU 最好 | 精度优先、有独立主机 |
| `onnx` | onnxruntime + pillow | 中等 | **边缘设备推荐**，比原生 PyTorch 快 2~3 倍 |
| `motion` | opencv | 很低 | 树莓派 / 只想知道"有东西在动" |
| `stub` | 无 | ~0 | 只用直播与录制，不做分析 |

用 ONNX 的话，导出一份模型放到 `model_path`：

```bash
pip install ultralytics
yolo export model=yolo26n.pt format=onnx opset=12
```

多路摄像头的经验值：`fps=2` 时，一台 4 核 x86 小主机跑 `onnx` 档大约能带 6~8 路；
再多就把不重要的几路 `--no-analyze` 关掉分析，只保留录制。

## 七、日常运维

```bash
python -m watchtower cameras                     # 各路在线状态与错误
python -m watchtower digest --day 2026-08-09     # 手工补一天的剪影
python -m watchtower go2rtc-config > go2rtc.yaml # 从数据库重生成引导配置
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8900/api/health
```

### 常见问题

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| `注册 go2rtc 失败：Connection refused` | go2rtc 没起 | 起 go2rtc，然后 `cameras` 或 `POST /api/cameras/{id}/sync` |
| 涂鸦摄像头过几分钟就黑 | 短效地址过期 | 正常，续期循环会自动重取；确认 `refresh_expiring` 线程在跑 |
| 萤石 HLS 播不出来 | 设备是 H.265 | 到萤石 App 把编码改成 H.264，或改用 `protocol=ezopen`（服务端分析将不可用） |
| 小米摄像头连不上 | 断网了 | 小米 P2P 每次建连都要向小米云换密钥；纯离线请改 `mode=micam` 或原生 RTSP |
| 事件一直是 0 | 检测器降到 `stub` | 看启动日志的「检测器：」行，按上表装依赖 |
| 剪影没有成片只有封面 | 没装 ffmpeg / 当天没有带片段的事件 | 装 ffmpeg；或确认 `record=true` 且录像目录有分段 |
| 推送太吵 | 阈值太松 | 调大 `push.min_score` 与 `push.aggregate_window` |
| 磁盘涨得快 | 分段录制 | 每路 1080p 约 1~2 GB/天；调小 `retention_days` 或对次要摄像头关 `record` |

### 磁盘估算

```
分段录像 ≈ 路数 × 码率(Mbps) × 10800 ÷ 8 ÷ 1024  (GB/天)
事件片段 + 缩略图 ≈ 事件数 × 3MB
剪影      ≈ 每天 15~40 MB
```

10 路 4Mbps、保留 30 天，大约需要 1.6 TB。上生产前先算这笔账。
