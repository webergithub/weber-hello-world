# 视频取证：同一性甄别与后期加工识别

> 面向权利方委托的盗版调查：拿到一个副本后，回答两个问题——
> **① 这是不是我们的作品？② 它被动过什么手脚？**
>
> 对应实现 `src/forensics/`，命令行入口 `forensics.js`。

## 0. 边界

本工具**只分析你已经取得的本地文件**，不负责获取。取证分析与样本获取本就不该耦合——
你手上的链接用 `curl -o` / `wget` 取下来即可，这个模块对任何来源的样本一视同仁。

## 1. 为什么从容器入手，而不是从画面入手

判断一个副本"有没有被二次加工"，最强的证据往往不在画面里，而在 **MP4 的样本表**里。

`stsz` 给出每一帧的字节数，`stts` 给出每一帧的时长，`stss` 标出哪些帧是关键帧。
把这三张表拼起来，**不解码任何一帧**就能还原出两条曲线：

| 曲线 | 来源 | 取证意义 |
|---|---|---|
| **逐秒码率剖面** | `stsz` + `stts` | 插入的广告是另一次编码的产物，码率分布几乎不可能与正片一致 |
| **关键帧节奏（GOP）** | `stss` + `stts` | 编码器的 keyint 是强指纹；正片一套参数、插入段另一套，节奏会突变 |

**两个信号必须同时命中才给高置信度**，这条规则挡掉了大部分误报：
打斗戏码率飙高只影响码率、不影响 GOP；而真正的拼接两者必然同时异常。

代价也低：解析一部 2GB 的片子只需读几 MB——顶层盒逐个跳过，只完整读取 `ftyp` 与 `moov`，
占 99% 体积的 `mdat` 根本不碰。

## 2. 四层证据

### 2.1 码率与 GOP 异常段（无需参考母版）

稳健统计：中位数 + MAD（中位数绝对偏差）。**不能用均值和标准差**——
它们会被待检测的异常段本身污染，样本越少污染越重；MAD 对最多 50% 的离群点免疫。

置信度构成：

| 项 | 权重 | 说明 |
|---|---|---|
| 码率偏离幅度 | 0.35 | 稳健 z 分数 |
| GOP 节奏同时异常 | 0.30 | 最强的单项证据 |
| 边界落在关键帧上 | 0.20 | 拼接点必须在关键帧，这是必要条件 |
| 时长落在插播区间 | 0.15 | 3–300 秒 |

### 2.2 编码溯源（无需参考母版）

x264 / x265 会把**完整编码参数串**写进 `©too` 标签；muxer 在 `hdlr` 的 name 字段留名
（`Lavf`=ffmpeg、`L-SMASH`、`HandBrake`、`Core Media`…）；ftyp 品牌反映封装目标。

两个额外判据：

- **faststart**：`moov` 被前移到 `mdat` 之前，说明这个文件为网页/渐进式播放**重新封装过**——
  摄制与母版流程通常不会这么做。
- **keyint 交叉校验**：参数串里声明的 `keyint` 换算成秒后，与样本表里**实测**的 GOP 中位间隔比对。
  声明 2.0s 而实测忽长忽短，说明成片在编码之后又经过拼接。

出现剪辑软件签名（Adobe / Final Cut / DaVinci）或多个编码器签名，直接判定 `reprocessed`。

### 2.3 与参考母版比对（最强证据）

**码率剖面的"形状"在重编码后基本保留**——复杂场景吃更多比特，这一点与码率档位无关。
两条曲线各自除以中位数归一化后，同一部片子的正片段相关性很高，不同内容接近 0。

于是插入检测变成序列对齐：沿两条曲线同步前进，相关性掉下去时在嫌疑副本上向前试探；
若跳过 k 秒后重新对上，这 k 秒就是**被插入的内容**，精确到秒。反之要在母版上跳过才对得上，
说明副本**删掉**了那一段。不解码、不受重编码与改分辨率影响。

三个防伪对齐的设计（都是踩过坑之后加的，见 §4）：

1. **一侧恒定时判为不相似。** 相关系数在方差为零时无定义。若退化成"比均值"，
   一段码率被拉平的广告就会和任何窗口都"匹配"，整条对齐随即失效。
2. **取最小的达标偏移，而不是相关性最高的。** 信号含周期成分时，整数倍周期处会出现
   伪完美对齐；取最大相关性反而选中伪解。
3. **限制重同步次数（默认 12 次）。** 这是判据不是性能考虑：被插播的副本有个位数的拼接点，
   不会有几百个。不设上限的话，几百个候选偏移里"总能"撞上高相关的位置（生日问题），
   两部完全不同的片子也会被对齐成"同一作品"。

此外，**分箱粒度默认不小于母版的 GOP**：I 帧比 P 帧大好几倍，分箱比 GOP 细的话，
剖面里会混进一个"每个 GOP 一次"的强周期成分，正好触发上面第 2 条的失效模式。

### 2.4 像素层：烧录水印与台标（需本机 ffmpeg）

**设计要点：让 ffmpeg 只做「解码 + 缩放 + 转灰度」**，输出裸 rawvideo，每帧恰好
`width×height` 字节。不用它的分析滤镜（signature/blackdetect 等）——那些依赖具体构建是否编入；
而 decode+scale+gray 任何构建都有。所有分析留在纯 JS，因而可以脱离 ffmpeg 单独测试。

- **静态叠加物检测**：跨全片每 10 秒采一帧，对这组帧算**逐像素时间方差**。
  方差近零的连通区域即叠加物候选——正片内容不可能在几十个不同场景里保持同一块像素恒定。
  输出归一化包围盒（乘以原始分辨率即得像素坐标）与角落位置。
  已排除贴满整行的区域（那是信箱黑边）。
- **感知哈希（pHash）**：32×32 灰度 → 二维 DCT → 取左上 8×8 低频区（丢弃 DC）→
  中位数阈值二值化成 64 位。中位数阈值使其对整体亮度变化免疫。用于逐帧内容比对。

> ⚠️ 像素层的**进程调用**未在开发环境实测：该环境无可用 ffmpeg
> （仅有 Playwright 自带的 `--disable-everything` 构建，无 H.264 解码器）。
> 容器层与帧分析算法均已离线验证，缺的只是这一层的 spawn 调用。

## 3. 用法

```bash
node forensics.js <嫌疑副本>                          # 单文件分析
node forensics.js <嫌疑副本> --reference <母版>       # 与母版比对
node forensics.js <嫌疑副本> --json report.json       # 导出机器可读报告
node forensics.js <嫌疑副本> --overlay                # 叠加水印检测（需 ffmpeg）
```

退出码便于接入批处理：`0`=未见加工 · `1`=可疑 · `2`=确认加工 · `3`=分析失败。

**证据固化**：报告含 sha256 + md5（流式计算）、文件大小、修改时间、分析时刻、工具版本，
使结论可被第三方复核。

实测输出节选：

```
🚩 结论：确认经过后期加工
    · 与参考母版内容覆盖率 99.3%，判定为同一作品
    · 检出 1 处插入内容，合计 20 秒
    · 码率与 GOP 双重异常段 1 处（高置信）

─── 后期加工检测 ───
  🚩 00:10:00 – 00:10:20（20s）  置信度 100%  suspected-insert
      该段码率中位 6794 kbps，全片基线 1875 kbps（3.62×，稳健 z=19.9）
      同一时段关键帧间隔为 0.52s，全片为 2s——该段使用了不同的编码参数
      起止点均落在关键帧上，符合拼接特征
```

## 4. 验证方式

36 个用例，全部基于**合成 MP4**：构造器可以精确指定"第 600 秒起插入 20 秒、
码率 3 倍、GOP 0.5 秒的内容"，再断言检测器在那个位置报出发现。
这样验证的是**检测能力**，而不是"代码没崩"。

开发过程中夹具本身暴露了两个必须记下的建模错误：

1. **插入段最初被写成"覆盖"而非"插入"**——只把那 20 秒的码率改掉，
   正片内容仍停在原时间点。对齐算法当然找不到位移，测试也就什么都没测到。
   真实插播会把插入点之后的内容**整体后移**，构造器必须让插入段消耗墙钟时间但不消耗正片时间。
2. **码率曲线最初用正弦叠加生成**——正弦是周期信号，整数倍周期处产生伪完美对齐，
   拿它测对齐算法等于在测一个退化输入。改用带种子的 LCG 白噪声 + 指数平滑，
   得到"局部相关、全局不重复"的曲线，不同种子之间才是真正不同的内容而非相位差。

这两条同时也是 §2.3 里那三个防伪对齐设计的由来。

## 5. 局限

| 局限 | 说明 |
|---|---|
| 容器层只支持 MP4 / MOV / M4V | MKV、AVI、TS 需要走 ffprobe 路径（适配器已备，未接入主流程） |
| 分片 MP4（fMP4）样本表在 `moof` 里 | 当前只读 `moov`，分片文件会报样本数为 0；已在报告里标出 `hasFragments` |
| 无参考母版时无法判定同一性 | 只能给出"是否被加工"，不能回答"是不是这部片" |
| 码率剖面对**同参数重编码**不敏感 | 若插入段与正片用完全相同的编码参数压制，两条曲线都不会明显异常；此时需依赖像素层 |
| 像素层需要 ffmpeg | 且只检测**静态**叠加物；滚动字幕、动态角标不适用 |
