🔌 检索后端

Google / Bing / 百度 / DuckDuckGo 都没有可直接用的免费官方 API，所以引擎检索自己实现了几条路。 默认的「自动」什么都不用配就能搜——用代码直接请求结果页、自己解析响应， 不需要这台机器上装浏览器。检索是在服务端跑的，服务器上通常既没有图形环境 也没有 Chrome，所以默认路径刻意不依赖它。

选「自动」时按已经配好了什么挑：有 SERP 服务走 api，有命令行工具走 cli， 都没有就走 http。自动不会挑到浏览器那两档——它们要这台机器上真装了浏览器， 想用请明确选。

http · 直接请求结果页

就是「发一个 GET，再从返回的 HTML 里把结果抠出来」。比开浏览器快一到两个数量级， 不用装东西也不花钱。抽取不依赖页面的 class 名——把所有链接捞出来 按规则筛（还原跳转包装、排掉引擎自家域名），所以引擎改版面了照样能出结果。

代价是更容易被认出来是脚本。框架里做了这几件事来减少被挡：请求头成套发送 （只改 User-Agent 反而更可疑）、带上跳过同意页的 cookie、按引擎分别限速并带抖动。 真被挡了会如实报「被拦截」而不是「没搜到」——这两件事的处理方式完全不同。

各家的难易程度差别很大：DuckDuckGo 的 html 端点最好抓，Bing、百度、Mojeek 次之， Google 时好时坏，Yandex 几乎必弹验证码（所以它会直接跳过 http 这一级）。

api · SERP 服务

最稳，但按次计费。serper / brave 直接填 key；接别家服务选 custom 再填 URL 模板。

占位符：{query} {engine} {limit} {page} {key}。

cli · 本机命令行工具

免费，但机器上要先装（ddgr、googler 之类）。命令按空白拆成参数逐个执行， 不经过 shell，所以检索词里有什么字符都只会被当成一个参数。

browser · 无头浏览器

这一档要求运行检索的那台机器上真装了浏览器。放在自己电脑上跑没问题， 部署到服务器上就未必——所以它不是默认，是选了才用。选「阶梯」时浏览器是 按需开的：http 能出结果就根本不会启动它。

好处是能过大部分反自动化检测；代价是慢一到两个数量级、吃内存，而且引擎改版面就得跟着改。 也可以把 URL 模板指向自建的 SearXNG，既不付费也不直接爬引擎。

想要免费又稳的话，最好的答案是自建 SearXNG：它替你去问 Google/Bing/DDG 并聚合成 JSON，不用抓 HTML、不会被反自动化拦。 在「检索来源」里加一个名为 searxng 的引擎，把实例地址填到上面的 URL 模板里即可。

结果常是脚本渲染的，页面 load 之后还要再等一会儿才取得到。

📌 优先来源

先查这些站点上有没有这部片子，命中就记一条取证记录 （地址 + 页面标题 + 发现时间，可选截图）。 只回答「在不在」，不解析播放地址——结果进线索列表， 不进播放/下载通道，也不会被加进媒体白名单。

🔎 检索来源

没有单独设数量的来源用这个值。

搜索引擎

勾选后按下面的数量取该引擎的前 N 条结果，每个引擎可单独设。

专用数据源

有专门的解析器，直接产出结构化片源，不依赖搜索引擎。

🌐 站点范围

默认留空，也就是不加限定、全网搜。 填了域名才会把它们拼成 site:a OR site:b 挂在检索词后面， 让引擎只在这几个站里翻。一行一个域名，清空即恢复全网搜。

填之前想清楚：范围越窄，引擎能发现的新东西越少。要是填的正好是那几个 已经有专用解析器的归档站，引擎这条线基本就白跑了——那些站专用数据源 已经直接查过一遍。

另外，这里跟能不能播放/下载没有关系。能被服务端代理的域名 由另一份白名单单独把关，在这里写什么都不会放行新域名；引擎搜到的其他 域名只会作为线索列出来。

⬇ 离线下载存到哪儿

默认存到你自己的机器。把服务部署到远程机器之后， 服务端的下载目录对你毫无用处——文件下到了别人的机器上。

选「本机」时，支持 File System Access 的浏览器（Chrome / Edge，且是 https 或 localhost）会让你选保存位置，然后分块并发直接写进去， 写完再读一遍算校验和。Firefox / Safari 没有这个接口，会退化成普通的 浏览器下载——字节不经过本页，所以校验不了，界面上会如实标注。

⏱ 检索预算

这几个数字直接决定一次检索发多少请求、花多少时间和钱。

检索词扩展（第一步）

每多一个词，请求数就多「引擎数 × 页数」一份。 默认 4 词 × 引擎数，再加推荐词补搜一轮。

嗅探甄别（第三步）

超出的按上游元数据判定，结果里会如实标注「未探测」。

模拟打开验证（第五步）

这一步真开浏览器解码、真发并发请求，比前四步贵得多。
