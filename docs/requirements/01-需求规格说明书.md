## 1. 文档说明

### 1.1 目的与范围

本文是 TrailMate 的**需求规格说明书**，回答「系统现在是什么」，由实现反推（as-built）。它不是开发日志；逐版改动见 §11 版本演进。范围覆盖三套并行实现：Web PWA、原生 iOS 12、原生 Android，以及配套的信令服务端与 CI 出包流水线。

每一条"现状"陈述均来自对代码的 grep / 走读核实；与旧文档（README / PR 描述）不一致处以代码为准，并在 §10.2 已知问题记录偏差。

### 1.2 需求编号约定

- **FR-x.y**：功能需求，x 为模块号。
- **NFR-x**：非功能需求。
- 平台差异用行内标注 **[Web] / [iOS] / [Android]**；无标注表示三端一致。
- 未实现能力写「❌ 未实现」，与已实现同样计入规格。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 群组 / 队伍 | 一次出游的人群集合。Web 侧称"群组"（6 位数字验证码）；原生侧称"队伍"（6 位字母数字队伍码），二者为不同码空间 |
| 队伍码 team | 原生 BLE mesh 的房间过滤键，默认 `public`（公共队）；同码才互通 |
| Mesh / 自组网 | 无蜂窝/WiFi 时，手机间经蓝牙直连组成的多跳网络 |
| 多跳 TTL 泛洪 | 每条消息带存活跳数（TTL），中继转发给"朋友的朋友"，msgId 去重防风暴 |
| MeshBus | 营地聊天与跟车位置复用同一条 BLE 链路的分发总线，按消息类型路由、按队伍码过滤 |
| 垫付 / 应收 / 应付 | 记账：某人先付款为垫付；结算净额为正=应收，为负=应付 |
| 信令服务器 | Web WebRTC 建连时转发 SDP/ICE 的中继，不承载业务数据 |

## 2. 产品概述

### 2.1 产品定位

面向自驾/露营/徒步等**朋友结伴出游**场景的一体化助手。核心场景：车队路上互相跟车不走散；到了没信号的营地也能群聊；出游花销 AA 记账、一键算清谁给谁转多少；顺带把对讲/群聊的声音变成卡通角色增加趣味。

### 2.2 目标用户与典型场景

| 用户 | 典型场景 |
|---|---|
| 自驾车队组织者 | 建队伍、发验证码/二维码拉人，路上在地图上看各车位置，用对讲机喊话 |
| 露营/徒步同行者 | 到无信号营地，靠蓝牙自组网发文字消息约集合点 |
| 出游记账人 | 记录每笔垫付与分摊人，出游结束一键得出各家应收应付与最少转账方案 |
| 带老人小孩的家庭 | 用旧手机（iOS 12 / Android 5）也要能装能用；变声逗小孩 |

### 2.3 设计约束与原则

- **C-1 最老设备优先**：目标含 iPhone 5s/6（iOS 12）与 Android 5.0 旧机。因 iOS 12 的 WKWebView 缺 `getUserMedia`/`BroadcastChannel`，Web 版无法在其上跑通实时能力，故另行实现**纯原生 iOS 12 版**（UIKit/Swift，零第三方依赖，`ios12/project.yml:8` deploymentTarget iOS 12.0）与**原生 Android 版**（`android-native/app/build.gradle:12` minSdk 21）。
- **C-2 无网可用**：营地与跟车位置共享在无蜂窝/WiFi 下经蓝牙 mesh 工作，不依赖服务器。
- **C-3 零信任中继**：Web 的信令服务器只转发 SDP/ICE，不落业务数据（`server/signaling.js:3`）；原生 mesh 无服务器。
- **C-4 不区分机型**：原生 iOS 与 Android 用**相同的 BLE Service/Characteristic UUID + 帧协议 + MeshBus 信封 + JSON 键**，故可跨平台互通。
- **C-5 记账零浮点**：金额一律用整数「分」，杜绝浮点误差（`ios12/Sources/Ledger/LedgerModel.swift:3`）。

## 3. 系统架构

### 3.1 三套实现与角色

| 实现 | 技术 | 角色 |
|---|---|---|
| Web PWA | React 18 + Vite 5 + TS，Capacitor 封装 | 跨平台演示与联网版；同机多标签走 BroadcastChannel，跨设备走 WebRTC |
| 原生 iOS 12 | UIKit / Swift 5，XcodeGen，无第三方依赖 | 老 iPhone 可装；BLE mesh 真机互通 |
| 原生 Android | Kotlin，osmdroid + zxing | 老安卓可装；BLE mesh 真机互通 |

设备在 mesh 中同时担任**外围**（广播 + GATT 服务）与**中心**（扫描 + 连接），即每台机既发布也订阅（`ios12/Sources/Camp/BleMesh.swift`、`android-native/.../BleMesh.kt`）。

### 3.2 拓扑与数据流

- **原生跨设备（离线）**：iOS/Android 手机经 BLE 直连，MeshBus 承载营地聊天（kindChat）与跟车位置（kindLoc），多跳泛洪覆盖"朋友的朋友"。
- **Web 同机**：多标签经 BroadcastChannel 演示互通。
- **Web 跨设备（在线）**：经信令服务器（默认 `:8787`）交换 SDP/ICE 后建 WebRTC P2P。
- **真正的跨机型互通成立于 原生 iOS ↔ 原生 Android**（同一 BLE 协议）。Web 为独立岛，不与原生 BLE 直接互通。

### 3.3 安全模型

- 队伍隔离：MeshBus 收端按队伍码过滤，仅同码消息入站（`ios12/Sources/Mesh/MeshBus.swift`，`android-native/.../MeshBus.kt`）。
- **端到端加密**（G-CM-3 已实现）：MeshBus 业务负载 AES-256-CBC + HMAC-SHA256（Encrypt-then-MAC，MAC 前 16B），密钥由队伍码经 PBKDF2-HMAC-SHA256（盐 `trailmate-mesh-v1`，10000 轮）派生；信封 team 明文仅用于分房，内容密文，错队伍码/被篡改/旧版明文一律丢弃（`MeshCrypto.swift` / `MeshCrypto.kt` / 夹具 `meshcrypto.mjs` 三端逐字节一致，含固定校验向量）。
- 信令服务器（G-SEC-1 已加固）：可选 `SIGNAL_TOKEN` 鉴权、80 条/10s 限流、64KB 消息上限、单 IP 32 连接上限、未鉴权连接禁转发；公网部署需反代 wss（`server/signaling.js`）。

## 6. 接口与协议规格

### 6.1 BLE Mesh 帧协议（原生 iOS/Android 一致）

| 项 | 值 | 出处 |
|---|---|---|
| Service UUID | `7b2f9a10-4c3d-4b8e-9f21-0a1b2c3d4e5f` | `BleMesh.swift:17` / `BleMesh.kt:48` |
| Characteristic UUID | `7b2f9a11-4c3d-4b8e-9f21-0a1b2c3d4e5f` | `BleMesh.swift:18` / `BleMesh.kt:49` |
| CCC 描述符 | `00002902-0000-1000-8000-00805f9b34fb` | `BleMesh.kt:50` |
| 帧头长度 | 13 字节 | `BleMesh.swift:20` / `BleMesh.kt:51` |
| 帧头布局 | 取 8 字节 msgId / 1 字节 ttl / 2 字节 seq / 2 字节 total（大端） | `BleMesh.swift:106` / `BleMesh.kt:270` |
| 单片负载 | 180 字节 | `BleMesh.swift:21` / `BleMesh.kt:52` |
| 最大 TTL | 4 跳 | `BleMesh.swift:24` / `BleMesh.kt:55` |
| 片间延迟 | 15ms × seq | `BleMesh.swift:111` / `BleMesh.kt:275` |
| 去重 | msgId 十六进制入 seen 集合，源头自标记避免回环 | `BleMesh.swift:70` / `BleMesh.kt:121` |

### 6.2 MeshBus 信封（承载层）

- 帧结构：取 `[kind(1)][teamLen(1)][team...][payload...]`（`MeshBus.swift:27`）。
- kind 取值：`kindChat = 1` / `kindLoc = 2`（`MeshBus.swift:9`，`MeshBus.kt:54`）。
- 收端按当前队伍码过滤，不同码丢弃（`MeshBus.swift:55`）。
- team 截断上限 32 字节（`MeshBus.swift:28`）。

### 6.3 业务消息（JSON over MeshBus）

| 类型 | 键 | 出处 |
|---|---|---|
| 营地聊天 kindChat | `mid / n / t / ts` | `CampFragment.kt:101` |
| 跟车位置 kindLoc | `id / n / lat / lng / ts` | `ConvoyFragment.kt:102` |

### 6.4 Web 信令接口（WebRTC 建连）

- 传输：WebSocket，默认端口 8787，可用环境变量 `PORT` 覆盖（`server/signaling.js:12`）。
- 加入：客户端上报 `{room, peerId}`，服务器按 room 分组转发信令；房间空则删除（`server/signaling.js:43`）。
- 无鉴权字段、无限流（见 §10.2）。

## 8. 服务端与部署

### 8.1 信令服务端

- 运行形态：Node + `ws` WebSocketServer，`node server/signaling.js`（`server/signaling.js:10`）。
- 关键参数：端口 `PORT` 默认 8787；内存 `rooms: Map<room, Map<peerId, ws>>`。
- 防护：**当前无限流、无鉴权、无 TLS**（明文 ws）。

### 8.2 发布流水线（GitHub Actions）

| 工作流 | 触发 | 运行器 | 产物 |
|---|---|---|---|
| `android-native-build.yml` | 改 `android-native/**` / 手动 | ubuntu-latest，JDK 17 | `trailmate-android-apk`（debug 签名，可直装） |
| `ios12-build.yml` | 改 `ios12/**` / 手动 | macos-15 | `trailmate-ios12-unsigned-ipa`（未签名，需重签） |
| `ios12-signed.yml` | 仅手动 | macos-15 | `trailmate-ios12-signed-ipa`（需 5 个 Apple Secrets + 付费账号） |

**真实的坑**：
- Pages 首次需仓库 `Settings → Pages → Source = GitHub Actions` 手动开启，否则部署报「Resource not accessible」；因此 deploy-pages 自动触发限定 master 分支，特性分支用手动触发避免反复报红（`deploy-pages.yml:11`）。
- 签名 IPA 需**付费开发者账号**导出证书与描述文件；免费 Apple ID 无法走通，改用 Sideloadly/AltStore 对未签名 IPA 重签（`ios12/SIGNING.md`）。
- Web 生产构建的资源基址随 `GH_PAGES` 变化（`vite.config.ts`）：Pages 构建用 `/weber-hello-world/`，本地预览用 `/`；用错基址会白屏。

## 10. 质量保障与已知问题

### 10.1 质量手段

- GitHub Actions 五条工作流做编译门禁：改动即触发，Android/iOS 原生分别产出可安装包，编译不过即报红。
- 跨平台 BLE 协议一致性经字节级核对（UUID / 帧头 / 信封 / JSON 键逐项对齐）。
- Web 版经 Playwright + 无头 Chromium 端到端走查（建群→记账→最优结算数值正确）。

### 10.2 已知问题（均经代码核实）

| 编号 | 级别 | 问题 | 触发条件 / 根因 |
|---|---|---|---|
| KI-1 | 高 | 营地「语音/视频」原生 mesh 未实现 | `MeshBus` 仅 kindChat/kindLoc 两类，无音视频类型；180 字节分片 + 15ms 泛洪无法承载实时音视频。宣称与实现不符 |
| KI-2 | 中 | Android 变声缺预设且算法不同 | `VoiceFragment.kt:31` 仅 6 预设，缺用户点名的小猪佩奇/孙悟空及机器人；用变速重采样，时长随之改变，与 iOS/Web 保时长听感不一致 |
| KI-3 | 低（已修复） | Web 摊分逐人金额曾与原生不一致 | 勘误：Web 一直有「最后一人吸收余数」（`split.ts:35-36`），总额并不会差 1 分——本文档 v1.0 初稿此处表述有误。真实差异是非末位成员取整方式（Web `Math.round` vs 原生整除），如 50÷4 时 Web 13/13/13/11、原生 12/12/12/14。已将 Web 改为 `Math.floor` 与原生一致，11 组除不尽金额逐人比对验收通过 |
| KI-4 | 中（已修复） | iOS MeshBus 订阅句柄累积 | 原 `MeshBus.swift:37` 按 kind 向数组 append 句柄，VC 重建时旧句柄不释放；已改为每类型单句柄 + onPeers 按 tag 顶替，与 Android（`MeshBus.kt:88`）行为一致 |
| KI-5 | 中 | 「WiFi直连/蜂窝」优先级未落地 | 授权提示宣称蓝牙→WiFi直连→蜂窝，但原生仅实现 BLE；iOS 无第三方 WiFi Direct API。Web 的 WebRTC 需信令服务器 |
| KI-6 | 高 | 信令服务器无鉴权/限流 | `server/signaling.js` 任意知道 room 者可加入转发；明文 ws；无速率限制 |
| KI-7 | 低 | Web 群码与原生队伍码不同码空间 | Web joinCode 6 位数字，原生 newTeamCode 6 位字母数字；跨 Web/原生 拼群不对齐（且二者本就不共享传输） |
| KI-8 | 低 | Android 未做小票 OCR | 记一笔无拍照识别入口，需手输金额 |
