## 1. 分析方法

- **Gap 定义**：Gap = 目标能力（PR）− 现状能力（FR + 代码事实）。
- **五元组**：每条 Gap = 现状(带证据) / 目标(引 PR) / 差距陈述 / 级别 / 关闭验收(破坏性)。
- **分级**：

| 级别 | 含义 | 判据 |
|---|---|---|
| L1 品类硬伤 | 决定"叫不叫得上这个品类名" | 品类核心承诺不成立 |
| L2 任务阻断 | 核心任务走不通 | 任务成功条件缺前提 |
| L3 健壮性 | 静默失败/在岗性/安全兜底 | 失效不可见或恢复不了 |
| L4 体验 | 可用但别扭 | 有绕行路径 |
| L5 工程债 | 用户不可见，拖慢演进 | 返工率/残留/不可测 |

- 与规划分工：本文只定差距/级别/次序，方案细节引 ② 对应 PR，不重复。

## 2. 现状能力基线

### 2.1 已达标应保持的能力（先记资产）

- **跨机型 BLE 互通**：iOS 与 Android 用逐字节一致的 UUID/帧头/信封/JSON 键，真正做到不区分机型（①§6，附录 B #1）。**优于行规**：多数同类只做单平台。
- **多跳 TTL 泛洪 + msgId 去重**：覆盖"朋友的朋友"，防广播风暴（①§6.1）。
- **记账整数分 + 最少笔数结算**：原生零浮点、贪心结算（①FR-4.3/4.5）。**优于行规**：多数 AA 工具只列每人应付、不给最优转账。
- **老设备可达**：纯原生 iOS 12 / Android 5 可装（①§2.3 C-1）。
- **离线优先**：营地文字 + 跟车位置无网可用（①NFR-2）。

## 5. 演进路线（版本映射）

### 5.1 路线总览

| 阶段 | 版本 | 主题 | 关闭 Gap | 出口标准 DoD |
|---|---|---|---|---|
| E0 | v0.2.0 | 稳定性与可测性收口（先行） | G-PF-3、G-LG-2、G-ENG-1 | 有内存 loopback mesh 夹具；结算/去重/分片可自动回归；iOS 改单句柄；Web 摊分与原生一致 |
| E1 | v0.3.0 | 底线健壮 | G-CM-2、G-DR-1、G-CM-3、G-SEC-1、G-LG-1 | 各条破坏性验收全过 |
